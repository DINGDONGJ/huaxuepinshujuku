## 项目概述

本项目是一个**专业化学品安全数据查询平台**，旨在为化工行业从业人员、实验室工作者、安全管理人员提供便捷的MSDS（Material Safety Data Sheet，化学品安全技术说明书）查询服务。

### 核心功能

- ✅ **智能爬虫**：自动从化工MSDS网站抓取完整的化学品安全数据
- ✅ **结构化存储**：将MSDS文档分解为16个标准章节，存储在关系型数据库中
- ✅ **多维度查询**：支持通过中文名、英文名、CAS号、别名等多种方式查询
- ✅ **专业展示**：Web界面提供分章节、格式化的MSDS内容展示
- ✅ **图片支持**：自动下载并展示GHS象形图、运输标签等关键图片
- ✅ **数据导入**：支持JSON文件批量导入

## 数据库设计思路

### 设计原则

1. **规范化设计**：遵循第三范式（3NF），减少数据冗余
2. **关系清晰**：通过外键关联，保证数据完整性
3. **查询高效**：为常用查询字段建立索引
4. **扩展性强**：预留字段，便于后续功能扩展

### 数据模型（ER图文字描述）

```
化学品 (1) ───────< (n) 化学品别名
   │
   │ (1)
   │
   └──────────< (1) MSDS文档
                    │
                    │ (1)
                    │
                    └──────< (n) MSDS章节
```

### 表结构详解

#### 1. 化学品表 (chemicals)

存储化学品的核心标识信息。

| 字段名 | 类型 | 说明 | 设计思路 |
|--------|------|------|----------|
| id | INT | 主键 | 自增ID，系统内部标识 |
| CAS号 | VARCHAR(20) | CAS登记号 | 化学品的国际唯一标识符，允许为空（部分化学品无CAS号） |
| 中文名 | VARCHAR(200) | 中文名称 | 必填，主要查询字段 |
| 英文名 | VARCHAR(200) | 英文名称 | 可选，辅助查询字段 |
| 分子式 | VARCHAR(100) | 化学分子式 | 化学专业人员常用查询依据 |
| EC编号 | VARCHAR(50) | 欧洲化学品编号 | 国际贸易常用标识 |

**索引设计**：
- 主键索引：`id`
- 唯一索引：`CAS号`（允许NULL）
- 普通索引：`中文名`, `英文名`

**设计考虑**：
- CAS号设置为唯一但允许NULL，因为部分化学品（如混合物）可能没有CAS号
- 中文名和英文名都建立索引，提高查询效率
- 字段长度充足，适应各种化学品名称长度

#### 2. 化学品别名表 (chemical_synonyms)

存储化学品的同义词、俗名、商品名等。

| 字段名 | 类型 | 说明 | 设计思路 |
|--------|------|------|----------|
| id | INT | 主键 | 自增ID |
| 化学品ID | INT | 外键 | 关联到化学品表 |
| 别名 | VARCHAR(200) | 别名内容 | 各种同义词、俗名 |

**关系约束**：
- 外键：`化学品ID` REFERENCES `chemicals(id)` ON DELETE CASCADE
- 级联删除：删除化学品时自动删除其所有别名

**设计考虑**：
- 一个化学品可能有多个别名（如甲醛：福尔马林、蚁醛等）
- 别名也建立索引，支持模糊查询
- 使用级联删除，保证数据一致性

#### 3. MSDS文档表 (msds_documents)

存储MSDS文档的元数据信息。

| 字段名 | 类型 | 说明 | 设计思路 |
|--------|------|------|----------|
| id | INT | 主键 | 自增ID |
| 化学品ID | INT | 外键 | 关联到化学品表 |
| 编制单位 | VARCHAR(200) | 编制机构 | MSDS编制方信息 |
| 编制日期 | DATE | 编制日期 | 文档时效性判断依据 |
| 修订日期 | DATE | 最后修订日期 | 追踪文档更新历史 |
| 编制依据 | TEXT | 编制标准 | 如GB/T 16483-2008 |
| 创建时间 | TIMESTAMP | 数据入库时间 | 系统管理字段 |

**关系约束**：
- 外键：`化学品ID` REFERENCES `chemicals(id)` ON DELETE CASCADE
- 唯一约束：`化学品ID`（一个化学品只对应一份MSDS）

**设计考虑**：
- MSDS文档与化学品是1:1关系
- 记录文档的编制和修订信息，便于追溯
- 创建时间自动记录，方便数据管理

#### 4. MSDS章节表 (msds_sections)

存储MSDS的16个标准章节内容。

| 字段名 | 类型 | 说明 | 设计思路 |
|--------|------|------|----------|
| id | INT | 主键 | 自增ID |
| MSDS文档ID | INT | 外键 | 关联到MSDS文档表 |
| 章节序号 | INT | 1-16 | 标准MSDS章节编号 |
| 章节标题 | VARCHAR(200) | 章节名称 | 如"化学品及企业标识" |
| 内容 | TEXT | 章节文本内容 | 核心数据 |
| 图片JSON | JSON | 图片数据 | 存储图片URL和本地路径 |
| 创建时间 | TIMESTAMP | 数据入库时间 | 系统管理字段 |

**关系约束**：
- 外键：`MSDS文档ID` REFERENCES `msds_documents(id)` ON DELETE CASCADE
- 复合唯一约束：(`MSDS文档ID`, `章节序号`)（一个文档的每个章节唯一）

**设计考虑**：
- 每个MSDS文档固定有16个章节
- 图片数据使用JSON格式存储，灵活支持多张图片
- 内容字段使用TEXT类型，支持大量文本

### 存储过程设计

为了简化常见查询操作，设计了`查询化学品`存储过程：

```sql
CALL 查询化学品('甲醛');        -- 中文名查询
CALL 查询化学品('50-00-0');     -- CAS号查询
CALL 查询化学品('福尔马林');    -- 别名查询
```

**实现逻辑**：
1. 先在`chemicals`表中通过CAS号、中文名、英文名查询
2. 如果找不到，再在`chemical_synonyms`表中通过别名查询
3. 返回完整的化学品信息、别名列表、MSDS文档和所有章节

**优势**：
- 封装复杂的多表关联查询
- 提供统一的查询接口
- 自动处理多种查询方式

```
  ↓
保存JSON文件
  ↓
（可选）导入数据库
```


## 前端显示优化

### 格式化设计原则

MSDS文档是专业技术文档，需要清晰的层级结构和视觉引导。

**格式化规则**：
1. **大标题**（紫色，带下划线）：章节主要内容区块
2, **小标题**（蓝色加粗）：子项目、属性名称
3. **普通文本**：描述性内容、数值

### 各章节格式化详解

#### 第1部分：化学品及企业标识

**格式规则**：
- "产品标识"、"推荐用途和限制用途"等 → 大标题
- 其他内容 → 普通文本

#### 第2部分：危险性概述

**格式规则**：
- "紧急情况概述"、"GHS危险性类别"、"GHS标签要素" → 大标题
- "象形图"、"信号词" → 小标题（蓝色）
- "急性经口毒性 类别3" → "类别3"为小标题
- H/P编码（如"H301"、"P301+P310"）→ 小标题（蓝色）

**特殊处理**：
- H/P编码可能跨行（"P301+" 和 "P310" 在不同行），需要合并
- H/P编码后跟描述文本

**实现示例**：
```javascript
// 处理跨行P编码
let code = 'P301';
while (i + 1 < lines.length && /^P?\d+\+?$/.test(lines[i + 1])) {
    code += lines[i + 1];
    i++;
}
// 读取描述
let description = '';
if (i + 1 < lines.length) {
    description = lines[i + 1];
    i++;
}
html += `<div><span class="blue-bold">${code}</span> ${description}</div>`;
```

#### 第3部分：成分/组成信息

**格式规则**：
- 第一行（化学品名称） → 大标题
- "CAS No."、"EC No."、"含量范围" → 小标题
- 对应的值 → 普通文本

**布局**：使用Flexbox横向排列标签和值

#### 第4-8部分：操作和防护措施

**格式规则**：
- "急救措施描述"、"灭火介质"等主要内容块 → 大标题
- "一般性建议"、"眼睛接触"、"适合的灭火介质" → 小标题
- 编号列表（"1. xxx"）→ 保持编号和文本在同一行

**编号处理**：
```javascript
// 合并跨行的编号
if (/^\d+$/.test(line)) {  // 纯数字
    if (i + 1 < lines.length && /^\./.test(lines[i + 1])) {  // 下一行是"."
        line = line + lines[i + 1];
        i++;
    }
}
```

#### 第9部分：理化特性

**格式规则**：
- 属性名 + 单位 → 小标题（蓝色加粗）
- 属性值 → 普通文本

**特殊处理**：
- 属性名可能跨行（"气味" 和 "临界值"需合并）
- 单位需要合并到属性名（"熔点/凝固点" + "(℃)"）

**实现示例**：
```javascript
// 合并多行属性名
let propertyName = line;
if (i + 1 < lines.length && !lines[i + 1].match(/[0-9]|无资料/)) {
    propertyName += lines[i + 1];
    i++;
}
// 合并单位
if (i + 1 < lines.length && /^\(.*\)$/.test(lines[i + 1])) {
    propertyName += ' ' + lines[i + 1];
    i++;
}
// 读取值
let value = lines[i + 1] || '';
html += `<div class="field">
    <span class="blue-bold">${propertyName}</span>
    <span>${value}</span>
</div>`;
```

#### 第10-13部分：稳定性和生态信息

**格式规则**：
- "稳定性和反应性"、"急性毒性"、"废弃处置" → 大标题
- "反应性"、"化学稳定性"、"LD50(经口)" → 小标题

**特殊处理（第11章LD/LC数据）**：
- 原始数据："LD" + "50" + "(经口)" + "7060mg/kg(大鼠)"（4行）
- 处理后："LD50(经口)" → 小标题，"7060mg/kg(大鼠)" → 值

**实现示例**：
```javascript
// 识别LD/LC数据
if (line === 'LD' || line === 'LC') {
    let label = line;  // "LD"
    i++;
    label += lines[i];  // "50"
    i++;
    label += lines[i];  // "(经口)"
    i++;
    let value = lines[i];  // "7060mg/kg(大鼠)"
    html += `<div class="field">
        <span class="blue-bold">${label}</span>
        <span>${value}</span>
    </div>`;
    i++;
}
```

#### 第14-16部分：法规和其他信息

**格式规则**：
- "国际化学品名录"、"运输信息" → 大标题
- 各国名录名称、运输标签 → 小标题
- "列入"、"未列入" → 普通文本（不是标题）

## 常见问题

### 安装和配置问题

**Q1: Playwright安装失败**

A: 尝试以下步骤：
```bash
# 设置国内镜像
set PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright/
playwright install chromium

# 或者使用代理
set HTTP_PROXY=http://127.0.0.1:7890
set HTTPS_PROXY=http://127.0.0.1:7890
playwright install chromium
```

**Q2: 数据库连接失败**

A: 检查以下配置：
- MySQL服务是否启动
- 用户名和密码是否正确（默认：root/1234）
- 数据库是否已创建（huaxuepin_db）

修改`app.py`中的数据库配置：
```python
connection = pymysql.connect(
    host='localhost',
    user='your_username',      # 修改用户名
    password='your_password',  # 修改密码
    database='huaxuepin_db',
    charset='utf8mb4'
)
```

**Q3: 端口5001被占用**

A: 修改`app.py`最后一行：
```python
app.run(host='0.0.0.0', port=5002, debug=True)  # 改为5002或其他端口
```

### 爬虫问题

**Q4: 爬取失败，显示超时**

A: 可能原因和解决方法：
- **网络问题**：检查是否能访问目标网站
- **页面加载慢**：增加等待时间
  ```python
  await page.wait_for_timeout(5000)  # 增加到5秒
  ```
- **反爬虫机制**：添加User-Agent和延迟
  ```python
  await page.set_extra_http_headers({
      'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...'
  })
  ```

**Q5: CAS号显示"未找到"**

A: 部分化学品（如混合物）可能没有CAS号，这是正常现象。系统会使用中文名作为索引。

**Q6: 图片无法显示**

A: 检查：
- 图片文件是否保存到`templates/images/`目录
- 文件权限是否正确
- 浏览器控制台是否有404错误

### 使用问题

**Q7: 搜索无结果**

A: 检查：
- 输入的关键词是否正确（CAS号格式：XX-XX-X或XXX-XX-X）
- 数据库中是否已导入该化学品
- 数据库连接是否正常

**Q8: 章节内容显示不全**

A: 可能是CSS样式问题，按`Ctrl + F5`强制刷新浏览器缓存。

**Q9: 如何更新已有化学品的MSDS**

A: 重新爬取相同CAS号的化学品：
```bash
python scrape_to_json.py "URL" --import
```
系统会自动检测并更新数据。

### 性能问题

**Q10: 查询速度慢**

A: 优化建议：
- 确保已创建索引（初始化脚本已包含）
- 清理旧数据：
  ```sql
  DELETE FROM msds_sections WHERE 创建时间 < DATE_SUB(NOW(), INTERVAL 1 YEAR);
  ```
- 升级硬件（更快的磁盘、更多内存）

**Q11: 数据库占用空间大**

A: 原因和解决：
- 图片数据占用空间大 → 考虑使用对象存储（如阿里云OSS）
- 历史数据积累 → 定期归档旧数据
- 日志文件占用 → 清理MySQL binlog
